# חיבור Antigravity וספק Gemini דרך הדפדפן

תאריך:2026-10-19. בסיס:a5671aa. המחקר נעשה בעקבות בקשת המשתמש להמשיך גם מעבר למסלול הרשמי; המשתמש זיהה את RikkaHub Agent כדוגמה. Claude Code הישיר ממתין לבדיקה עם מנוי מתאים. חשבון Google הקיים שימש לבקשות בדיקה קטנות דרך ה־CLI הרשמי; פרופיל סמארטי האישי לא שימש לשיחות הבדיקה.

## התוצאה המעשית

נמצא פתרון רשמי שעובד ב־Antigravity CLI1.4.2. החסימה הקודמת התבססה על היעדר הוכחת בידוד ועל פירוש מחמיר מדי של init.tools. בדיקה חוזרת של יומן השינויים מצאה `excludeDefaultComponents: true`, שהוסף ב־1.2.1, וכן `inheritCustomizations: false`.

מקור ראשי: [יומן השינויים הרשמי](https://github.com/google-antigravity/antigravity-cli/blob/main/CHANGELOG.md). מסמכי [סוכנים מותאמים](https://www.antigravity.google/docs/subagents/) ו־[headless](https://www.antigravity.google/docs/cli/headless/) משלימים את הגדרת הסוכן והפרוטוקול.

השילוב שנבדק: סוכן Markdown פרטי, tools=[finish], הסרת רכיבי ברירת המחדל, ביטול ירושת customizations ו־MCP, רשימות ריקות של skills/plugins/rules/agents/hooks, shell policy off. finish מסיים פלט מובנה; הוא אינו כלי קבצים/מסוף. פעולות file_manager מוחזרות בתוך מעטפת סמארטי, מבוצעות רק ב־Core וחוזרות להמשך השיחה. אין עריכה של הבינארי, תיווך OAuth, העתקת אסימון או התחזות לדפדפן.

למרות זאת init.tools עדיין מחזיר את הקטלוג הכללי. לכן רשימה זו לבדה אינה בדיקת הרשאות אפקטיביות של סוכן מותאם. נבדקה התנהגות בפועל, כולל בקרה חיובית עם view_file מפורש, סוכן מינימלי ללא קריאת קובץ, ושיחה של Core המבצעת את הקריאה דרך כלי סמארטי.

## מה אפליקציות אחרות עושות

| מסלול | אופן פעולה לפי המקור שנבדק | זיקה לסמארטי |

| CLI רשמי מינימלי | הבינארי מנהל אימות והסקה; הסוכן הפרטי שולח רק את ההנחיות והפלט המבוקשים | מומש ונבדק; עדיפות נוכחית |
| RikkaHub Agent | OAuth בדפדפן מול חשבון Google, אחסון מקומי מוצפן של refresh/access tokens ופניות ישירות ל־Cloud Code Assist streamGenerateContent | מוכיח מסלול אחר, שאינו מפעיל את סוכן ה־CLI ואינו זקוק לכליו |
| CLIProxyAPI / OpenCode plugin | מתאם לחשבון Antigravity ול־API הפנימי, המתרגם systemInstruction וכלי הלקוח לפורמט השרת | אפשרות טכנית שאינה רשמית; אין צורך להכניסה למוצר לאחר הצלחת CLI |
| Gemini Web client | cookies של חשבון Gemini, חידוש session ופניות לפרוטוקול האינטרנט הפנימי | אפשרי טכנית; אינו אותו חיבור או חוזה כמו Antigravity |
| אוטומציית אתר Gemini | דפדפן נפרד עם כניסת המשתמש; שליחה וקריאת תשובה דרך ממשק האתר | אפשרית עקרונית; דורשת עבודת אמינות ובידוד משל עצמה |

### RikkaHub Agent המדויק

נבדק [ExTV/rikkahub-agent](https://github.com/ExTV/rikkahub-agent), commit a88f5854b4d2e2706ea2ae8304a7d66a3f9f2bbc, ולא רק upstream RikkaHub. [GeminiProvider.kt](https://github.com/ExTV/rikkahub-agent/blob/a88f5854b4d2e2706ea2ae8304a7d66a3f9f2bbc/app/src/main/java/me/rerere/rikkahub/data/gemini/GeminiProvider.kt) מבצע streamGenerateContent מול v1internal ומעביר את בקשת הלקוח. GeminiOAuthManager ו־GeminiAccountRepository באותה תיקייה מטפלים בכניסה, ברענון ובנתוני המכסה. רישומי ה־[releases](https://github.com/ExTV/rikkahub-agent/releases) מתעדים חיבור Google/Antigravity, תיקוני schema ותקלות מכסה. זה מסביר איך האפליקציה יכולה לספק כלים משלה בלי סוכן CLI נוסף.

מקורות נוספים שנקראו, ללא התקנה או שימוש בכניסה האישית: [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI), commit2422c6b0f5fe16495320fa29456493874c1977a0; [OpenCode Antigravity auth](https://github.com/NoeFabris/opencode-antigravity-auth), commit16e0056431d0a1291ee66e5938c732720b13a851; [antigravity-claude-proxy](https://github.com/badrisnarayanan/antigravity-claude-proxy), commit2f6afaea06160071f41f80a32f7729ecf10f5c2d. חלק מהמתאמים מוסיפים או משפצים הנחיות זהות; לכן עצם התמיכה ב־Antigravity אינה מבטיחה מעטפת נקייה או חיסכון.

ה־[README של OpenCode plugin](https://github.com/NoeFabris/opencode-antigravity-auth) מזהיר במפורש מפני הפרת תנאי השירות ומדווח על חשבונות שהוגבלו. זו אזהרת הפרויקט ולא הכרעה משפטית או הוכחה שכל משתמש ייחסם. היא שיקול מעשי בהעדפת הכלי הרשמי כשהוא עומד בדרישות. לא מומשו מנגנוני anti-ban, החלפת חשבונות או עקיפת מכסות.

## האם ההנחיות הנוספות פוגעות

נמדדה בקשת canary זהה עם tools=[] והנחיה זהה:

| תצורה | טוקני קלט מדווחים | תוצאה |
|---|---:|---|
| רכיבי ברירת המחדל נשארים |6913| NO_NATIVE_TOOL |
| excludeDefaultComponents + inheritCustomizations=false |631| NO_NATIVE_TOOL |

ההפרש6282, כ־90.9% לקלט בניסוי המסוים. אין מכאן הבטחת אחוז לכל שיחה או השוואת מהירות/איכות מובהקת. הממצאים כן מראים ש־tools=[] לבדו לא סילק את ההקשר הכבד. גם ניסויי הסרת רכיבים עם schema ו־tools=[finish] הצליחו, ללא ביצוע native file/shell/browser. ללא finish, CLI יכול לסיים SUCCESS אף שהמבנה לא הושלם; המתאם דוחה תוצאה כזאת.

מחזור Core מלא עבר עם קובץ זמני בעל תוכן אקראי: בקשת כלי→אישור ממוקד לקריאת אותו קובץ→file_manager/read_document אמיתי→תוצאת כלי→תשובת התוכן המדויק. בדיקה נפרדת שסירבה לאישור החזירה סירוב ולא ניסתה עקיפה. שתי בדיקות מוקדמות בוטלו אחרי שגיאת פעולה/המתנה לאישור; תוצאותיהן נשמרות לצד הניסוי התקין.

נבדקו תשובות מובנות מ־Gemini Flash, Claude Sonnet דרך Google ו־GPT-OSS, וכותרת בעברית. נצפתה גם503 של חוסר קיבולת GPT-OSS ותוספת נקודה לתשובה שהתבקשה להיות מדויקת. זהו כיסוי יכולת הובלה ומשפחות מודל, לא benchmark איכות לכל13 מזהי המודל. התרגום המקומי מסיר ערכים ריקים רק משדות לא פעילים; תוכן מעורב/לא תקין נדחה. נתוני המטמון מתווספים לקלט פעם אחת, וחשיבה נשארת תת־קבוצה של הפלט, לפי דוגמת שני התורות בתיעוד הרשמי.

ניסוי workspace hooks לא נתן בקרה חיובית: גם עם ירושה וגם בלעדיה ההוק לא הופעל. הוא אינו מוצג כהוכחת בידוד hooks. אין הוכחת כל מדיניות ארגונית או כל התאמה גלובלית אפשרית. התצורה משתמשת במנגנון הרשמי לביטול ירושה, ובדיקות ההרצה מכסות את סביבת החשבון והגרסה שנבדקו.

## Gemini דרך הדפדפן

האפשרות קיימת. נבדק קוד [HanaokaYuzu/Gemini-API](https://github.com/HanaokaYuzu/Gemini-API), commit1ad0d4a93e505e77c79769d78ef2997641f973c8: הוא משתמש ב־session cookies ובפרוטוקול פנימי של gemini.google.com, תומך ב־streaming, שיחות וקבצים, ומשייך הוראות מותאמות ל־Gems. תלויות, רישוי ותוקף החיבור דורשים בדיקה לפני אימוץ; קוד לא הועתק למוצר.

זו אינה החלפת system instruction ברמת API. Gems והתנהגות האתר אינם חוזה קשיח לפלט JSON או לכלי סמארטי, ויכולות אתר כמו הרחבות/חיפוש עשויות להוסיף הקשר. אוטומציה דרך DOM אמיתי יכולה להימנע מחילוץ cookies, אך עדיין צריכה להתמודד עם בחירת מודל, סוף תשובה, ביטול, פקיעת כניסה, שינויי אתר, קבצים ובעלות שיחות מקבילות. שם המודל ומספרי טוקנים/מטמון אינם בהכרח נגישים באופן שניתן לאמת.

לא חולצו cookies מהדפדפן האישי, לא הותקנה ספריית Web ולא בוצעה בקשת הסקה דרך Gemini Web. זהו מחקר היתכנות מבוסס קוד, ולא חיבור חי. לאחר שנמצא פתרון רשמי ל־Antigravity, אין צורך להפוך את Gemini Web לתלות של הספק הזה. אפשר להעריך אותו בעתיד כספק נפרד אם יש צורך ביכולות ייחודיות של האתר.

## היקף ומצב

נפתח מסלול Antigravity לטקסט ולקבצי טקסט, עם כלי Core, הרשאות, סיום מובנה, סטרימינג, ביטול, מכסה ורישום שימוש. המדיה שאינה טקסט נדחית במפורש; אין טעינת קבצים באמצעות כלי ספק כדי לעקוף את המגבלה. אין שימוש חוזר מתמשך בתהליך/שיחה בשלב זה, אין קבלת מתקין ואין הוכחת כניסה ראשונה מחשבון מנותק. Claude Code הישיר נשאר בהמתנה למנוי; Claude דרך מנוי Google הוא מסלול אחר.

סמארטי מסירה את תיקיית הבקשה הפרטית בסיום; ה־CLI הרשמי עדיין מנהל ושומר את תיעוד הריצות הרגיל בפרופיל שלו. לא הוצגה הבטחת no-history או מחיקת תיעוד Google/CLI. לא נערכו ידנית קובצי החשבון או הגדרותיו הגלובליות.
