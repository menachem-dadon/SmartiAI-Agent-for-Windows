# בנייה ואריזה של Smarti ל־Windows

נקודת הכניסה הקבועה היא `scripts/build_and_package.ps1`. היא מיועדת גם לבנייה הראשונה וגם לכל בנייה מאוחרת, ומשתמשת במתכון Tauri הקנוני ב־`build_tauri_release.ps1`. סקריפטי `ux6` הם כלי QA היסטוריים; אין צורך להפעילם לבנייה רגילה. `build_release.ps1` הוא מסלול PyQt הישן.

פתח PowerShell בתיקיית המאגר. ללא פרמטרים נבחר מספר הגרסה הנוכחי מתוך `desktop/package.json`:

```powershell
pwsh -NoProfile -File .\scripts\build_and_package.ps1
```

מספר גרסה ושם לבחירתך:

```powershell
pwsh -NoProfile -File .\scripts\build_and_package.ps1 -Version 0.88.0 -Label "ניסוי"
```

`Version` הוא מספר בשלושה חלקים, למשל `0.88.0` (אפשר גם `V0.88.0`). `Label` הוא שם החבילה: תווית במניפסט ובתיקיית התוצרים, ולא שינוי של מספר הגרסה המוצג בתוך האפליקציה. מספר הגרסה מסונכרן ב־Python, ב־Tauri, ב־Cargo ובקובצי npm **רק בעותק הבנייה**. קובצי העבודה שלך נשארים ללא שינוי; לקביעת גרסת המקור במאגר נדרשת משימה נפרדת.

| אפשרות | משמעות וברירת מחדל |
|---|---|
| `-Version` | מספר הגרסה; ברירת מחדל: גרסת המקור הנוכחית |
| `-Label` | שם קצר לחבילה, לרבות עברית; ללא תווי נתיב או תווים אסורים בשם קובץ |
| `-OutputDirectory` | תיקיית התוצרים; ברירת מחדל: `release` במאגר. בכל ריצה נוצרת בתוכה תיקייה חדשה |
| `-WorkRoot` | תיקיית עבודה קצרה עם תווים באנגלית, מחוץ למאגר; ברירת מחדל: `C:\SmartiAI-builds` |
| `-InstallerCompression lzma` | דחיסת המתקין הרגילה, ברירת המחדל |
| `-InstallerCompression zlib` | חלופה למהירות אריזה, בדרך כלל עם מתקין גדול יותר |
| `-OfflineInstaller` | מצרף את מתקין WebView2 המלא. בלי המתג מצורף bootstrapper (מתקין קטן שמוריד WebView2 אם הוא חסר). אינו מבטיח שבניית המקור עצמה תעבוד ללא רשת |
| `-SignedUpdater` | מפעיל חתימת עדכוני Tauri באמצעות סודות שהוגדרו בסביבה; אינו חתימת המפרסם של Windows |
| `-PrepareOnly` | מקפיא את המקור ומסנכרן גרסה בלבד. אין הידור, הורדה או אריזה |
| `-SkipPackageSmoke` | מדלג במפורש על בדיקות הפעלת החבילה; המניפסט מסמן שאין ראיית קבלה שלהן. ברירת המחדל היא להריץ אותן |

דוגמה עם תוצרים בכונן אחר ומתקין הכולל WebView2:

```powershell
pwsh -NoProfile -File .\scripts\build_and_package.ps1 -Version 0.88.0 -Label preview -OutputDirectory "D:\SmartiPackages" -OfflineInstaller
```

להכנה בלבד או להצגת העזרה:

```powershell
pwsh -NoProfile -File .\scripts\build_and_package.ps1 -Version 0.88.0 -Label preview -PrepareOnly
Get-Help .\scripts\build_and_package.ps1 -Full
```

נדרשים Windows, PowerShell7 (`pwsh`), Git, Python, Node/npm, Rust וכלי הבנייה של Windows עבור Tauri. Python יוצר סביבת build נפרדת, והתלויות מותקנות לפי מתכון המאגר. Cargo וארכיוני runtime (סביבת ההרצה הפרטית) משתמשים במטמון תחת `WorkRoot`; המקור, Core והחבילה נבנים מחדש לכל ריצה. הארכיונים המאוחסנים נבדקים על פי hashes נעולים. אין שימוש חוזר אוטומטי ב־Core ישן.

הבנייה מבודדת תיקיות נתונים, keyring (אחסון מפתחות), חשבון CLI ופרופיל WebView. אין העתקת חשבון אישי. הריצות המשתמשות באותו מטמון מסודרות באמצעות נעילה; שימוש ב־WorkRoot אחר נותן מטמון נפרד. הסקריפט אינו מוחק בניות קודמות, אינו מפעיל מתקין ואינו מפרסם את התוצרים.

בתיקיית התוצרים החדשה מתקבלים מתקין NSIS, ‏ZIP נייד, מניפסט בנייה עם hashes ותוצאות בדיקות ההפעלה, ומניפסט המקור עם זהות הקוד ושינויי הגרסה. הנתיב המלא מודפס בסיום. גרסה חדשה באותה תווית אינה דורסת ריצה קודמת. הקובץ הנייד מפעיל `SmartiAI.exe` לאחר חילוץ כל ה־ZIP.

ברירת המחדל היא בנייה מקומית ללא חתימת updater. כדי להשתמש ב־`-SignedUpdater` נדרשים `TAURI_SIGNING_PRIVATE_KEY`, ‏`SMARTI_UPDATER_PUBLIC_KEY` ו־`SMARTI_UPDATER_ENDPOINT` בסביבת הבנייה. המניפסט מציג בנפרד את מצב Authenticode (חתימת המפרסם ב־Windows). יצירת חבילה מקומית אינה בדיקת התקנה/שדרוג/הסרה במכונה נקייה או אישור הפצה.

אימות הסקריפט: בדיקות הכנה/גרסה/בידוד ומסלול `PrepareOnly` אמיתי עברו. הבדיקה אינה טענה שבנייה חדשה מלאה או התקנה בוצעו אחרי תיקון הקלט האחרון; מקור וראיות חבילה מופיעים בנפרד ביומן UX.
